# 题库质量分析（2026-11-13）

## 一句话结论

现在 App 里 **156,282 道唯一题，14,358 道（9.2%）被标为做不了并自动隐藏，可用 141,924 道**。
坏题数量不是「又冒出来的」，是**我之前的统计口径太窄 + 今天新增了两条规则**。

## 一、为什么从「128 道」变成「1.4 万道」

| 阶段 | 口径 | 数字 |
|---|---|---|
| 11-12 晚 | 103,257 题，只查 R1–R6（缺材料 / 缺答案 / 解析数字被吞 / 答案解析矛盾 / 图片键缺失） | 128（0.12%） |
| 11-13 凌晨 | 扫粉笔 id 空间补了 **53,025 道**（其中图表题占比很高） | — |
| 11-13 下午 | 你截图实证：图形题选项是 `["A","B","C","D"]`、题干图还挂 CDN → 新增 **R8 / R9** | 16,245（10.4%） |
| 11-13 晚（本轮） | R9 修正：公式图在 images.db 里能查到的不算坏（误杀 3,867 道） | **14,358（9.2%）** |

三条关键事实：

1. **R1–R6 抓不到「选项是字母占位」和「图还挂 CDN」这两种坏法**。R8/R9 是今天才加的，所以不是「坏题变多」，是「以前看不见」。
2. 扫进来的 5.3 万道是**扫描直取**，粉笔返回的题干里就是 `fb.fbstatic.cn` 的绝对 URL，本机不下载就是破图——这属于「已知代价」，需要单独的图片包解决（见第四节）。
3. R9 第一版过严：3,867 道题的公式图**在本地图片库里都有**，App 会按 latex key 换成 data URI，离线也能显示，被我误判成坏题。已修，救回这 3,867 道。

## 三、质量到底怎么样（按能不能做题）

| 判定 | 数量 | 说明 |
|---|---:|---|
| 完全可做 | 141,924 | 题干、选项、答案、解析齐，图本地可显示 |
| 隐藏：图缺（可救） | 9,478 | 主因是 tarzan 真图（9,598 道引用）没下载，下载后可放回 |
| 隐藏：选项占位 | 4,303 | 图形题选项图没采到，属于粉笔侧就没给图，基本救不回 |
| 隐藏：其它 | 577 | 打码 102、公式丢 124、答案解析矛盾 56、缺材料 24 等 |

按科目看用户实际感受：

- **公基**（0.8% 坏）：接近干净，9.9 万题可用里最稳的一块；
- **职测**（7.9%）：7,000 道题目可用，图表题里有一部分被拦，随机抽到坏题的概率约 1/12；
- **行测**（19.1%）：资料分析图表题集中，抽到坏题概率接近 1/5 ——这是目前最该补的；
- **申论/综应**：几乎没有「做不了」的题，但**解析覆盖低**（69.6% / 36.4%），主观题解析本来就是要点式，AI 批改可以补位。

## 四、要不要把图补回来

R9 的 9,478 道里，9,598 道引用 `fb.fbstatic.cn/api/tarzan/images/…`（题图、图表、折线图）。这些图现在**还能下载**（实测 200，image/png），做法是：

下载 → 等比缩到宽 500 / JPEG q60 → 存进 `images.db`（key 取 URL 的 hash）→ 把 `src` 改写成 `…formulas?latex=<hash>` → App 现有的 hydrate 逻辑直接就能显示。

规模估算：约 1.2 万张，原始 ≈ 500 MB，压缩后 ≈ 150–200 MB。三种放法：

1. 直接打进 APK：安装包 225 MB → 约 400 MB（不推荐）；
2. 单独「图片包」增量下载（App 内「下载完整图片」按钮，Wi-Fi 下点一下）：推荐；
3. 先只补图形推理 / 资料分析：约 5,000 张、80 MB，最划算的第一步。
