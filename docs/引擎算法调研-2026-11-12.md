# 离线刷题 App 智能出题引擎：算法调研与技术建议

> 对象：Android 考公/考编刷题 App（Capacitor + 本地 SQLite，完全离线、无后端）
> 现状：硬编码 Leitner + 手写难度系数 + 配额 + 薄弱考点抽样 + 难度带 + 36 题初始测评
> 目标：判断能否换成「自学习」算法，而不是继续堆 if
> 版本：v1.0（2026-11）

---

## 0. 结论摘要（先看这一页）

**一句话**：你的数据规模决定了「能做自学习，但只能在『用户级参数』这一层做」，题目级参数（难度/区分度）在离线单机下**数学上不可估**。所以正确的路线不是「换一个更聪明的模型」，而是**把可学的部分（用户能力 θ、考点掌握度、记忆稳定性 S）从硬编码里拆出来做在线贝叶斯更新，把不可学的部分（题目难度）用先验 + 收缩估计顶住**。

四条硬结论：

1. **A 档（立刻可做，约 600–900 行 TS）**：`1PL/Elo + Glicko 式不确定性` 估用户能力，`分层收缩` 估难度先验，`ZPD(目标正确率 0.75–0.9) + Thompson sampling` 选题。不需要任何训练数据，第一次答题就开始学，预测粒度足够驱动选题。**收益主要来自「难度带」和「薄弱考点 70%」这两条规则被连续化、个性化**。
2. **间隔重复不要自己写**：直接用 `ts-fsrs`（TypeScript，可直接进 Capacitor 包），FSRS-6/FSRS-7 的 21/34 个权重出厂即用；**单用户在线优化参数在你这个数据量下不可靠**（社区/文档经验阈值是数百到上千条 review 才稳），A/B 档只用「固定权重 + 可调 desiredRetention + maximumInterval」，C 档才做 per-user 拟合。
3. **BKT/DKT/AKT/SAINT/DKVMN 全部不进端**：pyBKT 自己的论文说参数收敛要 ~50 名学生（learn/slip）、~100 名（guess/prior）——这是**学生数**，你一个用户就是 1。DKT 类要 10⁵–10⁸ 条交互（EdNet 是 1.31 亿条）。它们只能出现在 C 档的后端。
4. **难度标注 78% 都是 5 这件事，端上无解，只能用先验 + 收缩**：1PL 下要 SE(b)≈0.3 logits 需要每题 ~100 次作答；你 9.8 万题 × 100 = **980 万条作答**才全校准一遍。单用户 500 条作答只能覆盖 0.5% 的题。可做的是：题型定 guessing 参数、按 chapter 做分层先验、用用户自身历史做题目级 EWMA 并强收缩（κ=10）。文本冷启动有论文（R2DE），但它的真值也是靠「≥100 名学生作答过」的题校准出来的。

**如果只能做一件事**：把 `难度带(<40%出易, >80%出难)` 换成 `p̂ = σ(θ_u − b_i)` 的连续打分 + 目标正确率 0.85 的选题（85% 法则，Wilson et al., *Nature Communications* 2019）。这一条改动最小、可解释、不引入任何训练。

## 1. 先把约束翻译成数字

| 量 | 数值 | 含义 |
|---|---|---|
| 题库 | 15 万行 / 9.8 万唯一题 | 行级有重复（多选选项行/解析行），去重键建议用题干 hash |
| 单用户作答 | 几十 ~ 几千条，取中位 **~500 条** | 训练样本量 |
| 题覆盖率 | 500 / 98000 = **0.51%** | 99.5% 的题对该用户是「零样本」 |
| 考点数 | 假设 150–300 个 keypoint | 每考点平均 **~2.5 条**作答 |
| 难度标注 | 0–9，但 78% 是 5 | 方差极小，本质是「无标注」 |
| 题型 | 单选 / 多选 / 判断 | 决定 guessing 参数 c，是免费的强先验 |
| 网络 | 无 | 不能跨用户、不能夜间批量训练、不能 A/B 上报（除非另开埋点通道） |

**这决定了三件事：**

- **可估**：用户级 1–2 个参数（能力 θ）、考点级偏移（收缩）、记忆稳定性 S（FSRS 已有公式）。
- **不可估**：题目级难度 b、区分度 a（每人每题 0–2 次观测）。
- **不可训**：任何神经网络（无跨用户数据就没有可学的共享结构）。

> ⚠️ 一个容易被忽略的领域事实：**考公刷题不是背单词**。法条/常识/时政属于「记忆型」，间隔重复（FSRS/HLR）直接适用；数量关系、资料分析、判断推理属于「技能型」，练的是解题程序，间隔重复的收益远小于「在 ZPD 内做变式练习」。**建议按题型/模块分流两套调度**，这比把 FSRS 套到全库更有效。后文 A/B 档都按这个前提设计。

## 2. 知识追踪与能力估计

### 2.1 方法总览与数据需求

| 方法 | 参数量级 | 训练数据需求 | 单机离线可行性 | 冷启动方案 |
|---|---|---|---|---|
| **BKT**（Corbett & Anderson 1995） | 4 参数/技能（prior, learn, guess, slip） | 每技能 ~50 名学生收敛 learn/slip，~100 名收敛 guess/prior；序列≥15 | ❌ 每人每考点仅 2.5 条 | 参数用文献默认 + 全局共享，只更新掌握概率 |
| **BKT 扩展**（KT-IDEM / KT-PPS / BKT+forget） | +题目或学生随机效应 | 同上 ×2–3 | ❌ | 同上 |
| **DKT**（Piech 2015） | LSTM ~10⁵–10⁶ 权重 | 10⁵–10⁶ 交互 | ❌ 无预训练权重可迁移 | 无（必须跨用户） |
| **DKVMN**（KDD 2017） | 同上 + 记忆矩阵 | 同上 | ❌ | 无 |
| **SAKT / AKT / SAINT / SAINT+** | Transformer 10⁶–10⁸ | 10⁶–10⁸（EdNet 1.31 亿条） | ❌ | 无 |
| **IRT 1PL**（Rasch） | 1/题（b）+ 1/人（θ） | θ：**20–30 答**即可 SE≈0.4；b：**100–300 答/题**（跨用户） | ✅ 若 b 用先验固定，**只估 θ** | b 用规则/文本先验 |
| **IRT 2PL** | +a（区分度） | b 需 200–500；a 需 500+（a 很难识别） | ⚠️ 只估 θ 可行 | a 全局常数或按题型 |
| **IRT 3PL** | +c（猜测） | 1000+/题 | ⚠️ **不要估 c，用题型算** | c=1/选项数（单选）、0.5（判断）、≈0（多选全对） |
| **Elo** | 1/人 + 1/题 | 从第 1 条开始 | ✅✅ 最契合 | b 用先验，K 衰减 |
| **TrueSkill / Glicko** | 1/人(μ,σ) + 1/题(μ,σ) | 同上，但**自带不确定性** | ✅✅ 推荐 | σ 初值即「冷启动置信度」 |
| **PFA**（Pavlik 2008） | 每 KC 2 个计数特征 + 每题的成败计数，~10–30 参数 | 每 KC 数百条 | ✅（SGD，端上可行） | 计数从 0 起，先验即冷启动 |
| **DAS3H**（EDM 2019） | logistic，特征=题偏置+技能+时间窗（lag）+练习量 | 每 KC 数千条 | ✅ 结构简单，但需跨用户才有意义 | 时间窗权重可用文献值 |
| **KTM**（因子分解机, AAAI 2019） | 嵌入维度 d×(题+技能) | 10⁴–10⁶ | ❌ 端上没必要 | — |

### 2.2 逐条点评

**BKT：结论是对的，但数据量差两个数量级。**
pyBKT 团队自己的数据充分性研究（arXiv:2105.00385）给出的是：learn/slip 约 50 名学生收敛，guess/prior 约 100 名，且每个技能的序列长度 ≥15 才能缓解「最差掌握度估计」。你一个用户就是一个学生，每个考点 2.5 条记录——**连一次 EM 迭代都撑不起来**。BKT 唯一可用的形态是：把 4 个参数当作**全库全局常数**（从 ASSISTments 文献值或你 36 题测评上拟合一次），只在线更新「掌握概率 P(L_n)」这一个隐藏状态（贝叶斯前向一步，20 行）。这其实就是「带学习率的 Elo」的另一种写法，收益不如直接上 Elo。

**DKT / DKVMN / SAINT：明确排除，但要知道它们错在哪。**
DKT 的核心价值是「跨技能迁移」（做几何题能提升代数题预测），这个能力**只能从跨用户数据里学**。你没有跨用户数据，就没有可学的共享结构，端上跑一个随机初始化的 LSTM 等于随机数。Riiid 的 EdNet（131,441,538 条交互 / 784,309 学生 / 13,169 题 / 293 skills，人均 441.2 条）是这类模型的标配燃料——注意它的人均交互数（441）和你的人均作答数（500）**是同一个量级**，差别在于它有 78 万个「441」。这就是差距的全部。

**IRT：真正可用的，但要接受「半 IRT」。**
1PL 下 `p = σ(θ_u − b_i)`。关键在于**只让 θ 动**：b_i 由先验给出并冻结，模型退化成「单参数在线估计 + 已知试题难度」，这正是能力测验（CAT）里 Rasch 模型的常规做法。
精度估算（Fisher 信息 = p(1−p) ≤ 0.25，实际取 0.2）：
- 36 题测评 → SE(θ) = 1/√(0.2×36) ≈ **0.37 logits**
- 100 题 → 0.22；500 题 → 0.10
**结论：你现有的 36 题初始测评已经能给出可用的 θ 先验**，别浪费它。它的正确用法不是「分难度档」，而是初始化 `θ ~ N(μ₀, 0.37²)`。

**Elo / TrueSkill / Glicko：在「样本极少」这件事上，它们是设计目标本身。**
Pelánek 在 *Computers & Education* 98 (2016) 的 "Applications of the Elo rating system in adaptive educational systems" 里系统论证了 Elo 用于自适应练习的可行性（他运营的实践系统就是 Elo 驱动）。比裸 Elo 更好的是 **Glicko/TrueSkill 的 (μ, σ) 双参数形式**：σ 天然表达「我不确定这个用户有多强」，新用户 σ 大 → 更新步长大 → 冷启动收敛快；答得多了 σ 缩小 → 自动变保守。这直接替代了你手写的「慢答不加级」这类补丁逻辑。

**推荐形态（A 档核心，约 60 行）：**

```
似然:  p = σ(θ − b_i)
先验:  θ ~ N(μ, σ²)
Laplace 更新（答对 r=1，答错 r=0）:
    μ ← μ + σ²(r − p) / (1 + σ²·p(1−p))
    σ² ← σ² / (1 + σ²·p(1−p))
时间衰减（能力会漂移 / 长期不练会遗忘）:
    σ² ← σ² + τ²·Δdays        （τ ≈ 0.05~0.1 /天）
```

`σ²` 的单向增长是这套东西的灵魂：它让「三个月没来」的用户自动回到探索模式，不需要 if。

**PFA / DAS3H：值得作为 B 档的「可解释中间态」。**
PFA 只用「该 KC 的练习次数/成功次数」做 logistic 回归；DAS3H 在此之上显式加了 **lag time（上次练习距今多久）** 与 **练习量分箱**，论文报告在 ASSISTments 上优于 DKT/SAKT 等深度模型，且模型本身就是一个 logistic（可解释、参数少、可 SGD 在线更新）。对刷题 App 来说，DAS3H 的特征集几乎是「为你的场景量身定做」的：题偏置、考点、距上次练习天数、累计练习次数。10–20 个权重，端上 SGD 每次答题更新一次，成本可忽略。

**KTM：不用。** 因子分解机需要为 9.8 万题学嵌入，等价于每题的「难度+区分度」向量，回到「不可估」的老问题。

### 2.3 冷启动的三种弹药（按优先级）

1. **题型 → guessing 参数**（免费、最硬）：单选 c=1/选项数，判断 c=0.5，多选（全对得分）c≈0。这解决了 3PL 里最难估的 c，避免「猜对 = 会」。
2. **层级收缩先验**：`global → chapter → keypoint → item` 四级，每级向上一级收缩。你有现成的 chapter/keypoint 结构，这是最被低估的资产。
3. **文本/结构特征难度先验**：R2DE（Benedetto et al., LAK 2020, arXiv:2001.07569）用题干+选项的 TF-IDF（top-N 词）训 RandomForest/SVR 预测 IRT 的 a、b；Cloud Academy 1 万题 / 230 万交互 / 1.7 万学生，平均 283 次作答/题，且**只保留被 ≥100 名不同学生作答过的题**作为真值。结论：文本特征可以做新题先验、减少 pretesting，**但不能替代校准**。对你意味着：可以离线（构建期）跑一个词袋/字符 n-gram 回归，产出 `b_prior`，但它只能解释一部分方差，别指望它替代作答数据。

## 3. 间隔重复调度

### 3.1 算法演进（够用版）

| 代 | 算法 | 核心 | 参数 | 状态 |
|---|---|---|---|---|
| 1987 | **SM-2** | `I₁=1, I₂=6, Iₙ=Iₙ₋₁·EF`，答错(q<3)重置；`EF ∈ [1.3, 2.5]`，按 q 调 ±0.1~0.8 | 1/卡（EF） | 仍是多数 App 的默认 |
| — | **Anki SM-2 变体** | learning steps、ease 250%、interval modifier、leech(8 次) | 少量全局 | 你现在的 Leitner 是它的粗糙版 |
| 2016 | **HLR**（Duolingo, ACL 2016） | `p = 2^(−Δ/h)`，`h = 2^(θ·x)`；x = 历史特征 | θ 线性权重（~10–20 维） | 论文：预测误差较基线降 45%+，日活 +12% |
| 2018+ | **Ebisu** | 贝叶斯（Beta/Gamma）记忆模型，JS 实现 | 每卡 3 参数 | 社区项目，非工业主流 |
| 2022 | **SSP-MMC**（KDD 2022） | 把「最小化复习次数」形式化为最优控制，理论推导出幂律遗忘曲线 | — | FSRS 的理论前身 |
| 2023→ | **FSRS-4/5/6/7** | 三变量（难度 D、稳定性 S、可提取性 R）DSR 模型，按 review 拟合 | v6: 21 权重；v7(ts-fsrs 默认): 34 权重 + 双痕迹 | Anki 23.10 内置，25.02 起新用户默认 |

**FSRS-6 的关键公式**（值得抄进设计文档，因为它是「可解释 + 可在线更新」的范式）：

```
可提取性:  R(t,S) = (1 + F·t/S)^(−d),     F = 0.9^(−1/d) − 1
间隔反解:  I(r,S) = (S/F)·(r^(−1/d) − 1)
初始稳定性: S₀(G) = clamp(w_{G−1})
初始难度:  D₀(G) = w₄ − e^(w₅(G−1)) + 1
难度更新:  D* = D + ΔD·(10−D)/9,  D' = clamp(w₇·D₀(4) + (1−w₇)·D*)
成功:      S'_r = S·[1 + e^{w₈}(11−D)S^{−w₉}(e^{w₁₀(1−R)}−1)·H_G·E_G]
失败:      S_f  = min( w₁₁·D^{−w₁₂}·((S+1)^{w₁₃}−1)·e^{w₁₄(1−R)},  C )
同日复习:  S'   = clamp(S·S^{−w₁₉}·e^{w₁₇(G−3+w₁₈)})
```

注意 FSRS 的 D（难度）是**卡片级**的，和你库里 `difficulty=5` 的静态标注完全是两回事：FSRS 的 D 是「这张卡对这个用户有多难」的**动态**量。这恰好绕开了你 78% 都是 5 的问题——**FSRS 的 D 不需要你的标注**，它从 review 历史里自己长出来。

### 3.2 能不能在 App 内按单用户在线更新参数？

**分三层回答：**

| 层 | 做什么 | 数据门槛 | 端上可行性 |
|---|---|---|---|
| **L1 用出厂权重** | 只跑调度器（scheduler），权重用官方默认 | 0 条 | ✅ 立刻可做 |
| **L2 少数超参自适应** | `desiredRetention`、`maximumInterval`、`learningSteps` 按用户目标日期/留存调 | 无需拟合 | ✅ 立刻可做 |
| **L3 真正拟合 21/34 个权重** | 用 optimizer 跑梯度下降 | 社区/文档经验：数百~上千条 review 起，且要跨天的真实 review 记录 | ⚠️ 边缘：TS 端上要 wasm + Worker，耗时秒级到分钟级，必须后台/充电时 |

**ts-fsrs 现状（2026，官方文档站）**：默认 `version: 'FSRS-7'`（34 权重、双痕迹 stabilityFast、支持小数天与同日复习），可回退 `'FSRS-3/4/4.5/5/6'`；`DefaultScheduler({ version, weights, desiredRetention=0.9, enableShortTerm=true, learningSteps:['1m','10m'], maximumInterval })`，带 `preview / rollback / forget / nextInterval`。官方 Optimizer 通过 `@open-spaced-repetition/binding`（Node napi）与 **`binding-wasm32-wasip1`（浏览器/WebView Worker 可用）** 提供 `convertCsvToFsrsItems` / `computeParameters` / `evaluateWithTimeSeriesSplits`（返回 logLoss、rmseBins）/ `computeOptimalSteps`；文档自述 Optimizer 仍为 beta，数据不足时会跳过批训练。

**对你的判断**：L3 在「单用户 500 条 review」下不建议开——24 个自由参数 / 500 样本 = 严重过拟合，而且你的 review 间隔是 Leitner 生成的（1/2/4/7/15/30），**训练分布和 FSRS 想工作的区间不匹配**（FSRS 需要 5–365 天的长间隔才有信息量）。正确顺序是：**先上 L1 让调度器自己产生合理间隔，攒 3–6 个月真实数据，再考虑 L3。**

## 4. 选题策略

### 4.1 四种候选的横向比较（在「每用户几百次作答」下）

| 策略 | 探索机制 | 500 次作答下表现 | 结论 |
|---|---|---|---|
| **UCB1** | `score = μ̂ + c√(ln n / n_i)` | ❌ 考点数 200 ≫ 平均每题被抽次数。`ln n` 项在 n 小时把大量从未抽过的臂推到最前，退化成「按 id 顺序遍历」 | 不用 |
| **Thompson sampling** | 从后验采样 θ̃ ~ N(μ,σ²)，按 θ̃ 打分 | ✅ 样本效率最高：无数据时后验 = 先验，等价于「按先验抽」，天然平滑；数据多了自动收敛到利用 | **主力** |
| **KST（知识空间理论）** | 用 prerequisite DAG 的 inner/outer fringe 定「下一步可学」 | ⚠️ 需要**经过验证的**前置关系图（ALEKS 级别的工程量 + 学科专家标注）；你的 chapter/keypoint 只是目录，不是 DAG | B 档以后，且需人工建图 |
| **DKT + bandit** | 学一个 KT 模型当环境模型，再 RL 选动作 | ❌ 环境模型本身训不出来（见 §2） | 不用 |
| **ZPD / 85% 法则** | 目标 `p̂(correct) ∈ [0.75, 0.9]` | ✅✅ 最简单、最可解释、有强实证支撑 | **主力** |
| **信息量最大化（CAT 式）** | 选 Fisher 信息 `p(1−p)` 最大的题（即 p̂≈0.5） | ✅ 但目标冲突：测量最优（0.5）≠ 学习最优（0.85） | 只用于**测评/诊断模式** |

**关键实证**：Wilson et al., "The Eighty Five Percent Rule for optimal learning", *Nature Communications* 10:4646 (2019) 证明在噪声下的二分类学习任务中，**最优训练正确率约 85%，不是 50%**。你现在的「正确率<40% 出易题、>80% 出难题」方向是对的，但阈值和形态都偏了：应该把目标设在 **0.8–0.88**，并且是**连续打分**而不是分段 if。

**推荐打分函数（A 档，约 200 行）：**

```
p̂ = σ(θ_u − b_i)                      # 1PL 预测
# 1) 学习增益项：目标正确率 0.85 的高斯窗
gain  = exp( −(p̂ − 0.85)² / (2·0.12²) )
# 2) 不确定性/探索项：θ 后验方差 × 该题能带来的信息量
info  = σ²_u · p̂(1−p̂)
# 3) 到期项（来自 FSRS/Leitner 的 due 判定）
due   = 1 if t ≥ I(r,S) else (t / I(r,S))^2
# 4) 薄弱考点加权（替代硬编码 70%）
weak  = 1 + λ·(1 − mastery_k)         # mastery_k 用考点级 EWMA 正确率
# 5) 覆盖约束（防「信息茧房」）
cover = 0 if 考点本周已达配额 else 1

score_i = w₁·gain + w₂·info·(1−due_norm) + w₃·weak·due + ε·cover_penalty
θ̃ ~ N(μ_u, σ²_u)  # Thompson：每轮重采一次 θ̃ 再算 p̂
```

**为什么 TS 比 UCB 稳**：TS 的探索强度由**后验方差**自动决定。新用户 σ² 大 → 乱抽（这正确，因为你确实不知道）；老用户 σ² 小 → 只做最优点（也正确）。UCB 的探索强度由「被抽次数」决定，在臂数远大于总试验次数时，它对**从未被抽过的臂**给出无穷大的偏好，等于强制冷启动遍历，用户体验是灾难。

### 4.2 一个必须加的约束：探索下限

纯贪心 + TS 会收敛到「用户会的题」——因为 p̂ 高 → gain 在 0.85 附近恰好也高，但**考点覆盖会塌缩**到少数几个强项。考公是**考纲驱动**的（行测五大模块、申论、公基），必须在打分里加：
- 每个模块/章节每周最低覆盖配额（硬约束）
- 每次会话至少 20% 来自「本周未练过的 keypoint」
- 长尾题（全库零样本且先验不极端）按 5% 比例兜底曝光，用于给未来攒数据

这不是「安全措施」，是**避免自适应系统退化成局部最优**的必要设计——文献里叫 filter bubble / 覆盖不足。

## 6. 三档落地方案

### A 档：立刻可做（0 训练数据，纯在线更新，600–900 行 TS）

**用什么**
1. **能力估计**：Glicko 式 1PL —— `θ ~ N(μ,σ²)`，Laplace 在线更新（§2.2 公式），b_i 冻结为难度先验。**约 150 行**。
2. **难度先验**：分层收缩，四级 `global → chapter → keypoint → item`。完全不用你的 difficulty 字段也可以跑（用题型 + 章节均值）；difficulty 只作为**弱特征**（系数 0.05 logit/级），因为 78% 都是 5 等于没信息。**约 120 行**。
3. **选题**：§4.1 的加权打分 + Thompson sampling（每轮从 `N(μ,σ²)` 采一次 θ̃）+ 探索下限约束。**约 200 行**。
4. **调度**：保留 Leitner，但把「间隔」改成由 `p̂` 驱动：`p̂` 高 → 间隔长；`p̂` 低 → 间隔短。也就是把「答对升一级」换成「按预测正确率反解间隔」。**约 120 行**（或直接跳到 B 档用 FSRS）。
5. **存储/迁移/开关**：SQLite 加 3 张表（`user_ability`、`item_prior`、`exposure_log`），加 feature flag 与「新老引擎影子对比」。**约 150 行**。

**数据从哪来**：只用本地已有的作答记录（题 id、对错、用时、时间戳）+ 题库元数据（chapter/keypoint/题型/选项数/题干长度）+ 36 题测评。

**在线更新公式**：见 §2.2 的 Laplace 更新 + `σ² ← σ² + τ²·Δdays`。

**预期收益**
- 预测能力（对下一次作答的 AUC）预计从规则基线的 ~0.60–0.65 升到 **0.70–0.78**（参照 pyBKT 在 ASSISTments 上的 0.76；你的题更难、样本更少，取区间下沿）。
- 用户体验指标更可靠：**日均答题数、7 日留存、模拟考分数增幅**。可解释性完全保留（θ 是一个数，p̂ 是一个概率，能画曲线给用户看）。
- 难度带从「3 段」变成连续，用户「太简单/太难」的反馈应显著下降。

**风险**
- **过拟合**：`τ` 太大会让 θ 抖动（每次答题都大改），太小则学不动。建议 τ=0.05/天、初值 σ²=0.15（对应 SE≈0.39，正好等于 36 题测评的精度）。
- **可解释性**：其实比现状更好——现在「难度≥4 间隔×0.8」没人能解释为什么是 0.8。
- **难度标注烂**：A 档不依赖它（b 主要来自收缩先验 + 用户自身 EWMA），这是选 A 档的重要原因。
- **反馈回路污染**：出题策略影响作答分布，作答数据又反过来训难度先验，会自我强化。必须靠 §4.2 的探索下限 + 曝光日志（记录「被抽到但没做」的题）来缓解。

---

### B 档：中期（端上小模型 + 预训练参数表 + 在线更新，+1500–2500 行）

**用什么**
1. **调度换 FSRS**：`ts-fsrs`，`version:'FSRS-6'`（先别用 7，7 的 34 参数+双痕迹对你数据量更不友好），`desiredRetention` 按「距考试天数」动态调（考前 30 天提到 0.95，平时 0.85），`maximumInterval` 设 **60–90 天**（考公周期 3–6 个月，Anki 的 36500 天上限毫无意义）。**约 250 行封装**。
2. **能力估计升级为 DAS3H-lite**：logistic + 8–12 个特征（题偏置、考点、距上次练习天数分箱、累计练习次数分箱、题型、时长归一化），端上 SGD 每次答题更新。**约 300 行**。这一步把「遗忘」显式建模进 p̂，比 A 档的纯 1PL 准。
3. **难度先验表（构建期生成，不打进训练）**：Node 脚本离线跑（题干字符 n-gram / 长度 / 选项数 / 是否含公式或图片 / 是否多选）→ 线性或 GBDT 回归 → 产出 `item_prior.csv` 打进 assets。**约 300 行脚本**（构建期跑一次）。注意：**没有跨用户作答数据，这个模型的标签只能来自你现有的 difficulty 字段（78% 是 5）或教研人工标的小样本**——所以它的价值主要是给「零样本题」一个比常数更好的起点，别期待太高。
4. **选题升级**：Thompson sampling 从「θ 的全局后验」下沉到「考点级 Beta 后验」（`Beta(α_k, β_k)`，α/β 由该考点答对/答错数 + 收缩先验累加），选择时按 `样本 p̃_k` 排序并混入 A 档的 ZPD 项。**约 120 行**。
5. **可选：端上小规模参数拟合**。仅在你攒到 **≥400 条跨天 review** 后开启，用 `binding-wasm32-wasip1` 在 Worker 里跑 FSRS optimizer，采纳条件是「本地 holdout logLoss 比出厂权重低 ≥0.01」。**约 250 行（含 Worker 与门槛逻辑）**。
6. **评测设施**：曝光日志 + 本地 replay 评测（按时间切分，绝不随机切分）+ 引擎版本影子对比。**约 300 行**。

**预期收益**
- 调度质量：FSRS 相对 Leitner/SM-2 在同等复习量下通常**减少 20–40% 的复习次数**达到同等记忆保持（这是 FSRS 社区的核心主张，Anki 官方也以此推荐）；对考公用户意味着「省时间」。
- 预测能力再提升 0.03–0.06 AUC（DAS3H 型特征 + 遗忘建模）。
- 可以开始做「考前冲刺模式」「错题重练模式」这类产品化功能，因为它们本质上是 `desiredRetention` 的不同取值。

**风险**
- **参数不可解释**：DAS3H 的 12 个权重对教研不可读。缓解：只暴露「p̂、掌握度、下次复习日」三个可解释量，权重锁在黑盒里。
- **FSRS 假设不匹配**：FSRS 假设「同一张卡反复复习」；刷题场景里**同一道题重复做**会记住答案（答案记忆污染），导致 S 虚高。必须区分「同一题」和「同考点不同题」，前者用 FSRS，后者用考点级掌握度。这是 B 档最大的落地坑。
- **过拟合**：L3 优化在小样本上会把权重拟合到「用户这周的状态」而不是长期记忆。

### C 档：长期（需跨用户数据 + 后端，+5000 行 & 一个服务）

**前提**：必须有联网埋点（匿名化作答流）和一个后端。这不是技术问题，是产品/合规问题——**在中国做 K12/职业教育类 App 上报作答数据，涉及个人信息保护与数据出境评估，必须先过合规**。

**用什么**
1. **题目级 IRT 校准**：`py-irt`（变分推断）或 `girth`（JMLE）在服务端跑 1PL→2PL。门槛见 §7：每题 ≥100 次（1PL）/ ≥300 次（2PL）作答。9.8 万题 × 100 = **980 万条**才全校准一遍。
2. **模型选择**：先用 DAS3H/PFA 这类可解释基线，再用 `EduKTM` / `pykt-toolkit` 跑 AKT/SAINT 对比。**只有当深度模型在时间序列切分的 holdout 上稳定超过 logistic ≥0.03 AUC 时才值得上**——大概率不会（EdNet 上 SAINT 领先幅度也主要来自数据量）。
3. **下发方式**：服务端产出 `item_params` 参数表（b、a、c）打包成版本化 assets，App 定期拉取（几百 KB）。**推理仍在端上**，保证离线可用。
4. **个性化**：端上保留 A/B 档的在线 θ 更新，服务端只提供**题目参数**和**群体先验**（按地区/岗位/学历分层的 θ 先验）。这是「联邦式」的最小形态，不需要端上跑训练。

**预期收益**：真正解决 78% difficulty=5 的问题——题目难度第一次有客观值；可以做「预测分数」「岗位竞争力」这类高价值功能；可以做跨用户的题目质量治理（区分度 <0.2 的题下架）。

**风险**：合规成本、冷启动期长（要 6–12 个月攒数据）、题目参数随考纲变化漂移（需要定期重校准）、组织上要养一个数据团队。

## 7. 难度标注问题：能不能用 IRT 反推？

### 7.1 结论先行

- **单体用户数据：不行。** 9.8 万题、500 条作答 → 99.5% 的题零观测；即便某题被做了 3 次，「3 次全对」的 95% 置信区间是 [0.29, 1.0]，对 b 的约束接近 0。
- **跨用户数据：可行，但有明确门槛**（见下表）。
- **文本特征做先验：可行，但只能做先验**（R2DE 的结论是「减少 pretesting，不能替代校准」）。

### 7.2 收敛所需样本量（可算的部分）

1PL 下单个题目参数 b 的 Fisher 信息 = `p(1−p) ≤ 0.25`，实际作答正确率 0.5–0.85 时取 0.13–0.25：

| 场景 | 每题作答数 | SE(b) 近似 | 判断 |
|---|---|---|---|
| 单用户 | 1–3 | > 1.0 logits | 无意义 |
| 单用户 | 30 | ~0.37（θ 已知的理想情况） | 仅够粗排 |
| 跨用户 1PL | 100 | ~0.22（联合估计实际 ~0.3） | **可用** |
| 跨用户 1PL | 300 | ~0.13 | 稳 |
| 跨用户 2PL | 300（b）/ 500+（a） | a 的 SE 常 > 0.3 | a 只分题型给常数 |
| 跨用户 3PL | 1000+ | c 仍不稳 | **c 用题型算，不估** |

对照 R2DE 的做法：它把「被 ≥100 名不同学生作答过」作为进入 IRT 真值集的门槛，最终 8k 题 / 230 万交互 / 平均 283 次作答每题。**这就是工业界的经验值：~100 起步，~300 舒服。**

### 7.3 那在离线单机下怎么办：四层替代方案

1. **题型 → c（硬先验）**：单选 `c=1/选项数`，判断 `c=0.5`，多选（全对给分）`c≈0`。这一条直接消掉 3PL 里最不可估的参数，并且修正「猜对=会」的系统性偏差。**改动量 < 30 行，收益最大**。
2. **chapter/keypoint 级经验难度（收缩估计）**：对每个考点算 EWMA 正确率 → `b_k = −logit(acc_k)`，然后向章节均值收缩：
   ```
   b̂_k = (n_k·b_k + κ·b_chapter) / (n_k + κ),   κ = 10
   ```
   你 200 个考点 × 2.5 条/考点 → 几乎全部收缩到章节层。这是**正确且诚实**的做法：承认「我不知道这个考点的难度，先按章节算」。
3. **题目级 EWMA（只对做过的题）**：`acc_i ← 0.7·acc_i + 0.3·r`，同样向 `b̂_k` 收缩（κ=5）。500 条作答会覆盖 300–400 道题，这些题的 p̂ 会明显准于零样本题。
4. **文本/结构先验（构建期一次）**：题干长度、选项长度方差、是否含数字/公式/图片、是否多选、是否「下列错误的是」这类否定式问法 → 线性回归到 b。**注意**：没有真值标签时，只能回归到你现有的 difficulty 字段（78% 是 5，方差极小 → 回归系数会趋近 0）。所以这一步在 A 档**不做**，在 B 档作为「零样本题的兜底」，在 C 档（有跨用户真值）才真正有价值。

### 7.4 一个反向建议

**别急着修难度标注，先修「难度标注的用途」。** 现状的 difficulty 字段被用来（a）调间隔 ×0.8/×1.15，（b）分难度带。这两件事都可以被 `p̂ = σ(θ−b)` 取代——一旦 b 来自作答数据（收缩估计）而不是标注，标注的 78% 噪声就不再是瓶颈。**修数据的 ROI 远低于换掉「依赖数据」的那两条规则。**

## 8. 对比表

| 算法 / 方法 | 数据需求 | 离线端上可行性 | 预期收益 | 主要风险 |
|---|---|---|---|---|
| **Leitner（现状）** | 0 | ✅ 已完成 | 基线 | 无法个性化；「慢答不加级」是拍脑袋；难度系数无依据 |
| **SM-2 / Anki SM-2** | 0 | ✅ 简单 | 略优于 Leitner | 无遗忘曲线建模；EF 单参数表达力弱 |
| **FSRS-6（ts-fsrs）** | 0（用出厂权重）；400+ review 才谈拟合 | ✅✅ 纯 TS，可直接打包 | 同等记忆保持下复习量 −20~40%；间隔更贴合个体 | 同一道题重复做会「记住答案」→ S 虚高；需按「题」与「考点」分流 |
| **FSRS per-user 拟合（wasm）** | ≥400 条跨天 review，理想 1000+ | ⚠️ 需 Worker + 后台，低端机耗时 | 进一步提升调度精度 | 小样本严重过拟合；Leitner 历史间隔分布与 FSRS 假设不匹配 |
| **HLR（Duolingo）** | 每用户数百条 + 特征工程 | ✅ 推理极轻（一个线性模型） | 论文：误差 −45%+ | 需要「半衰期」真值；刷题场景的半衰期定义模糊 |
| **BKT（pyBKT）** | 50–100 名学生/技能 | ❌ 单用户不可估 | 掌握概率可解释 | 参数不可识别；每考点 2.5 条数据 |
| **DKT / DKVMN / SAKT / AKT / SAINT** | 10⁵–10⁸ 交互 | ❌ 无跨用户权重 = 随机数 | SOTA 预测（有数据时） | 无数据即无模型；端上算力/包体 |
| **IRT 1PL（只估 θ）** | θ：20–30 答；b：先验 | ✅✅ 60 行 | 预测 AUC 0.70–0.78；连续难度 | b 依赖先验质量 |
| **IRT 2PL / 3PL** | 200–1000 答/题 | ⚠️ 仅 c 用题型固定时可用 | 区分度可分题型 | a、c 不可识别 |
| **Elo** | 从第 1 条起 | ✅✅ | 冷启动最快 | 无不确定性表达；K 难调 |
| **Glicko / TrueSkill（μ,σ）** | 同 Elo | ✅✅ 推荐 | 自带冷启动置信度；自动降探索 | 参数（τ、初值 σ）需调 |
| **PFA** | 每 KC 数百条 | ✅ | 可解释、可在线 SGD | 特征太粗，跨考点无迁移 |
| **DAS3H（logistic）** | 每 KC 数千条（跨用户更佳） | ✅ 8–12 特征，SGD | 显式建模遗忘与练习量，优于深度基线（论文） | 权重不可解释；需特征工程 |
| **KTM（FM）** | 10⁴–10⁶ | ❌ 端上无必要 | — | 等于给每题学难度向量，回到不可估 |
| **UCB1 选题** | 每个臂多次拉动 | ✅ 但表现差 | — | 臂数 ≫ 试验数时退化为遍历 |
| **Thompson sampling** | 先验即可 | ✅✅ 推荐 | 样本效率最高，冷启动平滑 | 需好后验（θ 的 σ²） |
| **KST（ALEKS 式）** | 专家标注的前置 DAG | ⚠️ 图要建 | 「下一步可学」很优雅 | 建图成本极高；你的 chapter 不是 DAG |
| **ZPD / 85% 法则** | 0 | ✅✅ | 有 Nature Comms 实证；最可解释 | 目标正确率需按题型调（记忆型 vs 技能型） |
| **信息量最大化（CAT）** | 0 | ✅ | 测量最优（p̂≈0.5） | 与学习最优（0.85）冲突，只用于测评模式 |

## 9. 建议路线（含工作量与验收）

**第 1 步（2–3 周，A 档核心）**
- 落地 Glicko-1PL 的 θ 在线更新 + 分层收缩先验 + ZPD/TS 选题打分。
- 加 `exposure_log`（抽到但未做也要记）与影子模式（新引擎只打分不出题，对比它和老引擎的选择差异）。
- 验收：离线 replay（按时间切分，用 t 之前的记录预测 t 的作答）AUC ≥ 0.70；用户「难度不合适」反馈率下降；日均答题数不下降。

**第 2 步（3–4 周，B 档前段）**
- 接 `ts-fsrs`，按「记忆型 / 技能型」分流调度；`desiredRetention` 随考期动态调整；`maximumInterval=90`。
- 验收：7 日/30 日留存、复习完成率、按考点的掌握度覆盖度。

**第 3 步（可选，B 档后段）**
- DAS3H-lite 替换纯 1PL；只在 holdout 上确实提升时才切换。
- 攒够 ≥400 条跨天 review 后，才开 wasm optimizer。

**第 4 步（需要产品决策，C 档）**
- 匿名作答流上报 + 服务端 IRT 校准 + 参数表下发。这一步的瓶颈是合规与运营，不是算法。

**评测纪律（很重要）**
- 绝对不要随机切分做评估——会造成「未来信息泄漏」，AUC 虚高 0.05–0.1。按时间切分。
- 「用户会不会做这道题」和「用户做这道题对不对」是两个任务，分开评估。
- 任何「自学习」上线前先跑 2 周影子模式，只出日志不出题。

---

## 10. 一句话总结

把一个**不可估的问题**（9.8 万道题的难度）伪装成可学习问题，是这个项目最大的陷阱；把**可估的问题**（这个用户现在的水平、这个考点的掌握度、这道题的复习时机）交给统计模型，是它能成功的唯一路径。A 档够用，B 档是正确的中期形态，C 档的收益取决于你能不能拿到跨用户数据——而那是产品与合规问题，不是算法问题。
