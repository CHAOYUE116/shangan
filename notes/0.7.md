之前「职测模块」下面只在一级模块显示「3/50」，点开二级（新思想 / 时事政治 / 图形推理…）全是 0 ——
因为二级的已做数走的是按章节名匹配的老逻辑，二级名（新思想）和章节名（政治理论）对不上，永远匹配不到 0 条。

### 三、难度：算了，但写在新列里

题库里原来那个 `difficulty` 字段没有信息量 —— 粉笔接口根本不下发每题难度（1,384 份整卷语料里 `difficulty` 100% 是 null），
库里那些 5 是早期整卷数据集的默认值：单选 53% 是 5、多选题 81% 是 5、判断题 86% 是 5。

所以按结构先验算了一个，**写进三个新列，老 `difficulty` 原样保留**：

- `difficulty_est`：1–9 的整数，给人看、给「简单/中等/困难」用
- `difficulty_b`：logit 值，给引擎算 `sigmoid(θ − b)` 用（比整数细）
- `difficulty_src`：`structural`，标明这不是标出来的、是算出来的

公式（可解释、可复算，没有黑箱）：

```
b = 题型(判断 −0.6 / 多选 +0.8 / 不定项 +1.0 / 单选 0)
  + 模块(数量关系 +0.9 / 资料分析 +0.7 / 判断推理 +0.4 / 言语 +0.1 / 常识 0 / 政治理论 −0.1 / 其他 +0.2)
  + 0.25·ln(1 + 题干长度/60) + 0.20·ln(1 + 材料长度/300) − 0.15·ln(选项数)
```

结果分布 4:1,530 / 5:57,591 / 6:39,673 / 7:4,328 / 8:6，标准差 0.334 —— 也就是：
**能区分题型和模块，但区分不了「两道都是资料分析单选题」谁更难**。这件事离线单机做不到，
按 IRT 的估计精度要求，每题要 ~100 次作答才能在数学上定住难度，需要后端或题库方给真难度。

### 四、能力引擎：每个考点记一本账

这是这次真正的实验。不再是「正确率 > 60% 就算会」这种阈值判断，而是每个考点维护四个数：

| 量 | 含义 |
| --- | --- |
| θ | 你在这个考点上的能力（logit，0 = 中等，越大越强） |
| rd | 不确定度（答得越多越小；久没练会变大） |
| c | 蒙对概率（四选一 0.25、判断 0.5、按选项数算） |
| last | 上次答这个考点的时间 |

答一道题就更新一次：

```
p  = c + (1−c) · sigmoid(θ − b)        # 预测你答对这道题的概率
K  = 0.4 · rd / (rd + 0.5)             # 不确定时改动大，确定时改动小
θ ← θ + K · (y − p) / max(0.35, 1−c)   # y = 1 答对 / 0 答错
rd ← max(0.18, rd × 0.985)             # 越练越确定
```

三个刻意的设计：

1. **用带难度的残差更新**，所以 θ 是「能力」而不是「正确率」——答对一道多选题，比答对一道判断题更能说明问题。
2. **除以 (1−c) 修正蒙**：判断题蒙对率 0.5，蒙对一次不该当成「你会了」。
3. **不拟合个人参数**：K、rd 初值、难度权重是拿 24 个模拟学生 × 1500 条作答扫出来的（见 `tools/lab-sim.mjs`），
   不是拿你一个人的数据拟合的 —— 一个人几十几百条记录，拟合出来的参数只会过拟合。

引擎状态存在本机 `sg_theta_v1`。第一次升级时把历史作答按时间正序回放一遍，之后每答完一题就地更新。

### 五、每日任务改成按能力抽题

之前：每科取「正确率最低的 3 个考点」，70% 的题从这三处抽，剩余随机补。
现在（仅实验版）：按 **θ 最低** 排，其余不变。差别在于 θ 已经扣掉了题型难度和蒙对，
不会再把「专挑判断题蒙对的人」误判成「这块学得好」。

实测（模拟器，14 题的一轮）：三个考点里最弱的两个各出 8 题和 4 题，剩余 2 题随机补；
首页「今日重点」显示的就是这两个考点。

「我的 → 实验室 · 自学习引擎」里多了一块：现在攒了多少考点、多少次作答、最弱的几个考点 θ 是多少，
以及一个「重建账本（回放历史作答）」按钮 —— 数据乱了可以重放，不用清数据。

原来那套「四种模型同台测 AUC」还在，用来判断这套东西到底有没有变准。

### 边界说明

- **不接后端**：你说了暂时不接，所以「题目级真难度」「群体先验」这两条最有价值的都没有做。
- **不动正式版**：`lab` flavor 才有实验室和能力引擎，正式版 `?flavor` 为空、`NativeDB.flavor()` 返回 `prod`，
  能力引擎整段不加载，每日任务还是老逻辑。
- **不动老数据**：新表 `question_keypoints_ext`、新列 `difficulty_est / difficulty_b / difficulty_src`，
  老字段一行没改；要回滚就 DROP 表 / 不加那三列，5 秒钟的事。


## 出题与复习：怎么证明有用

这一版把「挑哪道题」「隔几天复习」两件事都换成了可对照的做法，并用离线模拟先算出差别（`tools/lab-policy.mjs`，同一批模拟学生、同一随机种子，学习增益函数与策略解耦）。

**选题（12 名学生 × 200 题，75 个可用考点）**

| 策略 | 总增益 | ZPD 命中 | 错题转化 | 覆盖考点 |
| --- | --- | --- | --- | --- |
| 按最弱正确率挑（0.6.2 现状） | 11.59 | 20.8% | 56.6% | 32/75 |
| 按 θ 最低挑（0.7 初版） | 11.73（+1.2%） | 19.4% | 54.1% | 75/75 |
| 纯随机（下界参考） | 12.73（+9.8%） | 22.7% | 58.9% | 70/75 |
| ZPD 0.85 无探索 | 8.80（−24.1%） | 9.9% | 95.5% | 75/75 |
| **ZPD 0.75 + 15% 探索** | **13.21（+14.0%）** | **30.5%** | **63.3%** | **75/75** |

结论：只盯「最弱」会长期喂太难的题，覆盖窄；目标正确率取 0.70~0.80 差别很小（+13.3% ~ +14.0%），取 0.75。

**复习排期（60 个知识点 × 90 天，同一记忆模型）**

| 档位表 | 复习次数 | 复习时平均保持率 |
| --- | --- | --- |
| 1/2/4/7/15/30（原表） | 947 | 64.0% |
| 1/1/2/4/9/18（实验版） | 949 | 70.8% |
| 按遗忘曲线排到 70% 保持率 | 896 | 70.3% |

结论：换成 FSRS 一类的曲线算法，在同等保持率下只省 7.5%，收益远小于调研预期；真正的问题原档位表把保持率压在 64%，加密一档（多 2 次复习）就能到 71%。所以实验版只加密档位，不引入新算法。

**真机上的两个数**（实验室面板「出题质量」）：`ZPD 命中率` = 出给你的题里预测正确率落在 60%~90% 的比例，`错题转化率` = 之前错过的考点下次做对的比例。这两个数比 AUC 更贴近「这套引擎对你有没有用」，也方便自己观察改动前后的变化。
